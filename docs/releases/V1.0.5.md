# CottageThermoESP V1.0.5 — passive learning HTTP reliability

**Field-test build only**. This changes the Waveshare thermostat's read-only learning telemetry, not the furnace controller or heating behavior.

## Observed reason for the change

November 14 V1.0.4 extended test: 3 successful /api/status reads of 28; 22 were HTTP transport failures and 3 were short controller IO lock misses. The regular control link had 3,661 successful HTTP requests and remained on LAN through 48 recovered grace windows and zero ESP-NOW switches.

## Improvements

- The five-minute read-only `GET /api/status` now uses a **dedicated persistent HTTP client**, separate from the authenticated controller `/api/link` control-session HTTP client. An origin change discards the old client; a failed transfer discards stale HTTP parser/transport state before the next scheduled observation.
- Increase read-only learning GET timeout from 2.5 seconds to a bounded **6 seconds**, without locking the normal control task for the network transaction.
- The low-priority learning task can wait up to **2.5 seconds** (previously 150 ms) to acquire the controller mutex for copying the verified origin, then immediately releases it before performing GET. It never holds the control mutex during network I/O.
- HTTP event-stage diagnostics distinguish failures before sending headers (connection/request setup), after sending headers but before response headers, and during response-body delivery. Additional reasons distinguish body overflow, non-200 HTTP status, empty response, invalid JSON, controller hostname mismatch, origin unavailable, and mutex busy.
- Read-only `GET /api/controller/diagnostics` reports learning request phase, full ESP error, HTTP status, elapsed milliseconds, response-byte count, response-header completion and whether the HTTP **client handle** was reused. A reused handle does not guarantee the same TCP socket survived.
- The last learning failure reason is retained in `/api/learning` and `/api/learning.csv`. The user-facing Link diagnostics page displays the expanded details.
- Host unit test covers stage classification, overflow handling and setup failures.

## Unchanged control and safety

- V1.0.4's LAN-first **60-second grace window**, actual Wi-Fi-loss immediate ESP-NOW fallback, authentication and status protocols.
- Controller firmware, servo PWM, calibrated dial positions, Live/freeze behavior, watchdog and local/manual override.
- No automatic learning-to-servo corrections; only candidate samples with fresh and validated controller observations can qualify.
- No additional retries or queued/replayed `TL_TARGET`, `TL_AWAY` or `TL_SAMPLE` control messages. Each observer sample performs only one read-only GET.

## Validation

Require successful host, browser, and ESP-IDF CI jobs. Install only the V1.0.5 **thermostat application `.bin`** using the existing onsite firmware update page. Do **not** install the controller artifact. After a period of normal operation download the link diagnostics JSON and learning CSV before rebooting. Target: learning GET success rate materially higher than 3/28 while 60-second LAN recoveries remain effective and ESP-NOW switch count stays near zero under brief network errors.

Passing CI does not prove controller GET reliability under the cottage network; physical field validation is still required.
